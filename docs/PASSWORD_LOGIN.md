# Executive password sign-in

Updated 15 October 2026 at the association's request. Executives now sign in with their invited email address and password, without an authenticator or an email code at each login. Invitation acceptance and password recovery still use the existing individual email links.

Migration `20261015060613_password_only_executive_login.sql` is installed as migration 22 on `hpbzhaleqphfucnautpl`. The database's MFA-required setting is false. Current contexts report password sign-in and never require MFA. The first President remains linked to member `SET2018-001`; no account, membership, financial or audit records were removed. The live project has no verified authenticator factors and no accounts blocked for MFA recovery.

Private RPC and RLS access require a live Supabase session with a signed `password` authentication-method claim. AAL1 password sessions are accepted. Invitation, recovery, email OTP or user-editable metadata alone cannot grant private access. Current role assignments, explicit grants/denials, schedules, pending appointments, revoked accounts, invalidated tokens and deleted Auth sessions retain their existing protections.

New invitations stay pending until the invitee sets their password and the client establishes a fresh password-authenticated session for the same Auth identity. Only then does the membership finalization RPC link/create the member and complete any approved replacement atomically. The old officeholder keeps access until that point. Password/recovery callback identity checks remain in place. Password input is not logged or stored outside the existing form/Auth flow.

The login and invitation/recovery password fields provide accessible Show/Hide buttons. These buttons change only input visibility, retain its value and autocomplete hints, expose the pressed state and never submit the form. Password setup disables its submit button while saving. Password-only account management hides obsolete authenticator-reset controls. Compatibility rendering for an older backend context remains available during deployment, but the current database does not request it.

Validation: the complete **347-test suite passed**, with no failures/skips; **52 modules** passed syntax checks; production and preview builds passed. New checks exercise ordinary AAL1 password access, denied invitation/recovery/OTP-only sessions, forged metadata, permissions, revocation, password visibility, direct sign-in, invitation password setup, pending access and hidden authenticator controls. Existing invitation tests now verify member enrollment and replacement after password setup without MFA. Advisor findings remain the guarded RPCs, intentional public event endpoint, deny-all internal tables, unused indexes and the pre-existing paid-plan leaked-password protection warning. No new unindexed foreign keys were reported.

No real passwords were entered by the agent, no verification/invitation emails were sent, and no real account was replaced during testing. A human President login and the first live executive invitation pilot remain to be completed. Custom SMTP is currently disabled: delivery of invitations/password-recovery emails to other executives still requires an association email-sending service. Normal password sign-in does not require SMTP.
